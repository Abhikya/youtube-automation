# Independent daily long-form stream

Shorts retain their registered channel configuration, three slots, prompts and portrait defaults.
`config.formats.longform_channel()` derives an immutable long-form profile for each existing channel.
It has the same channel key and OAuth credentials, a `longform` content format, one 21:00 slot,
and separate state/artifact/output/memory namespaces. Long-form story history uses the existing
canonical story identity code unchanged, against only that channel's long-form memory.

## Operations (not deployed)

The existing production workflow accepts `prepare_longform` and `cleanup_longform` in addition
to its unchanged default `prepare` and existing `cleanup`. Long-form uses a separate concurrency
group per channel. No scheduler service or cron entry is provisioned by this change.

An external dispatcher can eventually invoke `prepare_longform` for each of the three channels
at 02:00 Asia/Kolkata (20:30 UTC on the preceding UTC date). Blank `day` means the next IST
calendar date. Example: November 27, 02:00 IST prepares November 28, 21:00 IST, represented by
`2026-11-28T15:30:00+00:00`. It uploads privately during preparation and schedules YouTube
publication; there is no 21:00 upload runner. Explicit current-day recovery requires an existing
batch. The shared controller retains upload claims, fingerprints, artifact checkpoints,
resumable transport, durable IDs, verification and fail-closed uncertain-upload behavior.
An existing ID is verified, never blindly inserted again. Explicit Studio-confirmed absence
can be reconciled with `--day YYYY-MM-DD --confirmed-not-uploaded-slot 21:00`.

State artifacts carry cumulative format-specific idea history across runners (90-day artifact
retention, refreshed with new checkpoints). Media uses the existing seven-day retention and
conservative successful-upload cleanup. Missing/expired required artifacts still need operator
review; ephemeral local media is not the durable upload authority.

## Generation and local inspection

Run `python run_longform_local.py --channel-key minute_mysteries` to generate exactly one local
video without uploading. Add `--resume` to continue that channel's saved local story after a media/render failure without repeating completed idea, script, metadata, scene or TTS generation. Completed renders are not regenerated by resume. The local command has no upload option. Do not invoke production
preparation as a local render test: preparation is deliberately an upload-capable operation.

The pipeline shares the existing OpenAI clients/models, canonical deduplication, guardrails,
TTS, stock retrieval and MoviePy/FFmpeg renderer. Long-form alone requests one independent idea,
650-900 spoken words, 18 section-oriented scene searches (up to two landscape clips each),
1920x1080 video, 8-14 second visual cuts, and metadata without `#shorts`. Script length has one bounded same-story correction attempt; it never switches topics to repair length. Landscape downloads have two attempts, streaming time/size limits, and atomic cache publication. Partial downloads never become cached clips. It rejects narration
outside 4-7 minutes using measured TTS duration. It does not stretch or pad narration.

TTS uses sentence-aware chunks capped at 65 words. Caption timing anchors to measured chunk
boundaries and estimates word positions within each chunk; this is not forced word alignment.
Music uses existing assets with crossfaded joins. When the music folder is empty, long-form
alone creates a quiet original ambient bed locally using the existing NumPy dependency.

Local progress is saved in `temp/<channel>/longform/audio/generation-progress.json` before render.
Final output and JSON details are under `output/longform/<channel>/`. These files and long-form
memory/cache files are ignored by git. A frame thumbnail is generated locally when possible.
`upload_custom_thumbnail` is an isolated, optional helper requiring an existing ID and verified
channel; it is not automatically invoked or allowed to block the MVP preparation pipeline.
Custom-thumbnail account eligibility and visual quality remain manual inspection concerns.

No real upload, deployment, commit or push is part of this local implementation/test task.
Offline tests prove routing/state contracts, not factual correctness or editorial quality.
Inspect the rendered story, footage, subtitles, music and metadata before authorizing uploads.
